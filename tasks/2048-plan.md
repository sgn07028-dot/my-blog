# 지침: 2048 웹앱 계획 작성 (Plan 단계)

## 역할
너는 이 프로젝트의 **Plan 서브에이전트**다. 2048 웹앱의 구현 계획을 세워 `apps/2048/spec.md` 한 파일로 저장한다. 코드는 쓰지 않는다.

## 사용자 요청
> 2048 게임을 만들어줘. 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임이야. 점수판도 넣어줘

## 프로젝트 맥락 (읽고 반영할 것)
- 프로젝트 루트: 이 저장소 폴더(`my-blog`)
- `CLAUDE.md`: 작업 사이클(Plan → Build → Review → Embed)과 웹앱 규칙. 반드시 먼저 읽는다.
- 블로그는 프레임워크·빌드 없이 HTML/CSS/JS(ES 모듈)로만 만든 정적 사이트다. `package.json` 없음.
- GitHub Pages의 하위 경로 `https://sgn07028-dot.github.io/my-blog/`에서 열린다. 모든 경로는 `/`로 시작하지 않는 **상대 경로**여야 한다.
- 블로그 디자인은 블랙 배경 + 네온(시안·핑크·그린·옐로) 터미널 느낌이다. 색 값은 `css/style.css` 맨 위의 CSS 변수(다크: `:root`, 라이트: `[data-theme="light"]`)를 참고한다. 웹앱은 자체 완결이어야 하므로 블로그 CSS를 링크하지 말고, 필요한 색 값은 앱 안에 복사해 쓰는 방향으로 계획한다.
- 블로그 테마 선택은 `localStorage`의 `theme` 키(`dark` 기본, `light`)에 저장된다. 앱이 같은 출처라 이 값을 읽어 테마를 맞출 수 있다.
- 글 목록 화면은 `index.html`이 아니라 `js/main.js`의 `renderList()`가 그린다(카드 마크업 `post-card`, 목록 `post-list`). 사이드바는 `index.html`의 `aside.sidebar`. 스타일은 `css/style.css`.

## 계획에 담을 내용
1. **기능 명세**
   - 4×4 보드, 시작 시 타일 2개, 이동마다 새 타일(2 또는 4) 생성 규칙
   - 이동·합치기 규칙(한 번의 이동에서 같은 타일은 한 번만 합쳐짐 등 정확한 규칙)
   - 점수판: 현재 점수, 최고 점수(`localStorage` 저장), 새 게임 버튼
   - 2048 달성 시 승리 안내(계속하기 가능), 더 이상 움직일 수 없을 때 게임 오버 안내
   - 입력: 방향키, WASD, **모바일 스와이프**(CLAUDE.md의 모바일 규칙)
   - 타일 이동·합치기·생성 애니메이션 여부와 `prefers-reduced-motion` 처리
   - 접근성: 키보드만으로 플레이 가능, 점수 변화·게임 상태를 스크린리더에 알리는 방법
2. **파일 구조**: `apps/2048/` 안의 파일 목록과 각 파일의 역할. 게임 규칙(순수 로직)과 화면 그리기를 분리할 것.
3. **디자인**: 블로그와 어울리는 네온 스타일, 다크/라이트 대응, 375px 모바일에서 보드 크기.
4. **Embed 계획**: 블로그 메인(글 목록 화면)에 웹앱 카드를 넣는 방법. 실제로 어떤 파일(`index.html`, `js/main.js`, `css/style.css` 중 무엇)을 어떻게 바꿔야 하는지 코드를 읽고 구체적으로 적는다. 카드에는 제목, 설명, 미리보기(이미지 또는 iframe)가 들어간다. 여러 웹앱이 늘어날 것을 고려한 방식(예: 앱 목록 매니페스트)을 제안해도 된다.
5. **Review 체크리스트**: Review 단계에서 확인할 항목(동작, 모바일, 콘솔 오류, 엣지 케이스).
6. **사용자에게 확인받을 결정 사항**: 정해지지 않은 선택지가 있으면 추천안과 함께 목록으로.

## 수정 범위 (반드시 지킬 것)
- 만들 수 있는 파일: `apps/2048/spec.md` **하나뿐**이다.
- 다른 파일은 읽기만 하고 절대 수정·생성·삭제하지 않는다.
