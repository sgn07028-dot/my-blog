# 지침: 2048 웹앱 검증 (Review 단계)

## 역할
너는 이 프로젝트의 **Review 서브에이전트**다. Build 단계에서 만든 2048 웹앱이 계획대로, 문제없이 동작하는지 검증하고 결과를 `apps/2048/review.md`에 기록한다. **코드는 고치지 않는다.** 수정은 Build 담당이 review.md를 보고 한다.

## 먼저 읽을 것
1. `CLAUDE.md`
2. `apps/2048/spec.md` — 특히 1장(기능 명세)과 5장(Review 체크리스트). 6장 결정 사항은 모두 추천안으로 승인됐다.
3. `apps/2048/` 아래 구현 파일 7개: `index.html`, `style.css`, `js/game.js`, `js/render.js`, `js/input.js`, `js/storage.js`, `js/main.js`

## Build 담당이 특히 확인을 부탁한 부분
- 빠르게 연속 입력할 때 합쳐지는 원본 타일이 정리되는지(`render.js`의 `flushRemovals`), DOM 타일 수가 보드 타일 수와 같은지
- 승리·게임 오버 오버레이는 이동 뒤 300ms 늦게 뜬다. 그 사이 입력이 막히는지, Esc 연타로 dialog가 강제로 닫힐 때(`close` 이벤트) 상태가 맞는지
- 375px에서 4~5자리 타일 글자가 칸 안에 들어가는지, 라이트 테마 타일(시안 `#00627a`, 핑크 `#a8007d` 등) 대비 4.5:1 이상인지
- 세로가 짧은 가로 모드 레이아웃, `?preview=1`에서 입력·저장이 꺼지는지
- 한글 자판 상태에서 WASD 동작(`event.code`), Ctrl/Cmd+방향키를 가로채지 않는지

spec과 다르게 구현된 점(Build 보고): `render.js`에 `setBest(n)` 추가, `reducedMotion`에 함수 허용, 보드 너비 `min(100%, 480px)`, 미리보기 모드에 점수판 없음, 오버레이를 `<dialog>`로 구현. 이 차이들이 문제를 일으키는지도 판단한다.

## 검증 방법
1. **코드 검토**: 계획과 맞는지, 버그·보안(`innerHTML`에 데이터 삽입 여부)·접근성·경로(모두 상대 경로인지) 문제가 없는지.
2. **로직 검증**: `node`로 `js/game.js`를 불러 `slideLine`과 `move` 규칙(spec 1.2 예시 전부, 이동 없음 시 새 타일 없음, 한 번만 합쳐짐, 승리·게임 오버 판정)을 확인한다. 테스트 스크립트가 필요하면 파일로 남기지 말고 `node -e` 또는 `node --input-type=module -e`로 일회성 실행한다.
3. **브라우저 검증**: 로컬 서버가 이미 `http://localhost:8000`에서 프로젝트 루트를 서빙하고 있다. 앱 주소는 `http://localhost:8000/apps/2048/`, 미리보기는 `http://localhost:8000/apps/2048/?preview=1`.
   - 내장 브라우저 도구(`mcp__Claude_Browser__*`)를 쓸 수 있으면 **새 탭을 만들어** 확인하고 끝나면 그 탭만 닫는다. 기존 탭은 닫지 않는다. 창 크기를 바꿨다면 마지막에 `desktop`으로 되돌린다.
   - 키 입력·스와이프는 실제 키 입력 또는 `KeyboardEvent`/`PointerEvent`/`TouchEvent` 디스패치로 시험한다.
   - 375px(모바일)·768px·1280px, 다크/라이트 테마, 콘솔 오류를 확인한다.
   - 브라우저 도구를 쓸 수 없으면 그 사실을 review.md에 분명히 적고, 확인하지 못한 항목을 "미확인"으로 표시한다. 확인하지 않은 것을 확인했다고 쓰지 않는다.
   - `localStorage`를 테스트로 바꿨다면 마지막에 `my-blog:2048:best`, `my-blog:2048:state` 키를 지워 원래대로 돌린다(`theme` 키는 원래 값으로 복구).

## review.md 형식
```
# 2048 Review
## 요약 (통과 / 수정 필요 / 미확인 개수)
## 수정 필요 (심각도 높은 순)
- [심각도] 파일:줄 — 문제 — 재현 방법 — 제안하는 고침
## spec 5장 체크리스트 결과 (항목별 통과/실패/미확인 + 근거)
## 참고 (사소한 개선 제안)
```

## 수정 범위 (반드시 지킬 것)
- 만들 수 있는 파일: `apps/2048/review.md` **하나뿐**이다.
- 앱 코드, spec.md, 블로그 파일, `tasks/`, `.claude/`는 읽기만 한다. 파일 삭제 명령은 쓰지 않는다.
