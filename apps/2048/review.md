# 2048 Review

검증일: 2026-10-15 · 검증자: Review 서브에이전트 · 대상: `apps/2048/` 구현 파일 7개

검증 방법
- **코드 검토**: 7개 파일 전부 읽음.
- **로직**: `node --input-type=module -e`로 `js/game.js`를 불러 6,274개 단언을 일회성으로 실행했고 모두 통과했다. 대상은 spec 1.2 예시 7개 × 4방향 × 줄 2개, 불변성, 새 게임 5,000판, 승리·계속하기, 게임 오버 판정, `deserialize` 잘못된 입력 10종, 이동 200회 동안의 row/col 일관성이다.
- **명암비**: 다크·라이트 색 변수의 WCAG 명암비를 계산했다. 다크 테마의 반투명 타일 배경은 `--color-surface-2` 위에 합성해서 계산했다.
- **브라우저**: 내장 브라우저 새 탭에서 `http://localhost:8000/apps/2048/`과 `?preview=1`을 확인했다. 입력은 `KeyboardEvent`/`PointerEvent` 디스패치와 실제 Tab 키로 넣었다. 확인한 폭은 375×812, 768×1024, 1280×800, 844×390(가로), 568×320(가로), 400×300(미리보기)이다.
  - 주의: 브라우저 패널이 숨겨진 상태(`visibilityState: hidden`)라 rAF·CSS 애니메이션·dialog `close` 이벤트가 스크린샷을 찍을 때만 진행됐다. 그래서 애니메이션의 **시각적 움직임은 보지 못했다**. 크기 측정은 `getAnimations().finish()` 뒤에 했다.
  - 테스트 뒤 `my-blog:2048:best`, `my-blog:2048:state`를 지웠다. `theme`은 원래 값(없음)으로 되돌렸다. 창 크기는 desktop으로 복구하고 테스트 탭만 닫았다.

- 수정 필요: **0건**. 1차 리뷰의 3건(중 1, 하 2)은 모두 고쳐졌고 브라우저로 확인했다. 회귀도 찾지 못했다.

## 수정 필요 (심각도 높은 순)

남은 항목 없음. 아래는 1차 리뷰에서 지적했고 2차에서 **해결을 확인한** 항목이다. 확인 내용은 "2차 재검증" 절을 참고한다.

- **[중 · 해결됨] `style.css:365` + `js/render.js:180-189` — 게임 오버 오버레이에 빈 버튼이 보인다**
  - 문제: `setButton(null)`이 `button.hidden = true`로 숨기지만 `.btn { display: inline-flex }`가 UA의 `[hidden] { display: none }`을 덮어써서 숨겨지지 않는다.
  - 결과: 게임 오버 dialog에 글자 없는 44×44 버튼이 그대로 보인다. 이 버튼은 Tab 순서에도 들어가고, 접근 가능한 이름이 없으며, 눌러도 아무 일도 없다.
  - 승리 오버레이를 본 뒤 게임 오버가 되면 "새 게임"이라는 글자가 남은 채 동작하지 않는 버튼이 된다(`data-action`만 삭제되기 때문).
  - 재현: state를 `{"version":1,"cells":[2,4,2,4,4,2,4,2,2,4,2,8,0,8,16,64],"score":500,"won":false,"keepPlaying":false}`로 넣고 새로고침한 뒤 ←를 누른다. 측정 결과 `#overlay-secondary`는 `hidden=true`인데 computed `display: flex`, 크기 44×44였다(스크린샷으로도 확인).
  - 제안: `style.css`에 `.btn[hidden] { display: none; }`을 추가한다(또는 전역 `[hidden] { display: none !important; }`).

- **[하 · 해결됨] `js/main.js:122-124, 267-272` — 이어하기한 판은 게임 오버 때 "최고 점수 갱신"이 나오지 않는다**
  - 문제: 로드할 때 `best`를 저장된 판 점수까지 맞춘 뒤 `bestAtStart = best`로 잡는다. 그래서 새로고침 전에 이미 기록을 넘긴 판이면 게임 오버 때 `newBest`가 false가 된다.
  - 재현: 이전 최고 0, 점수 500인 판을 불러와 게임 오버 → "최종 점수 500 · 최고 점수 500"이 나온다(갱신 문구 없음).
  - 제안: `bestAtStart`를 저장 상태에 함께 넣는다. 또는 판정을 `newBest: state.score > 0 && state.score >= best`로 바꾼다(이전 기록과 동점일 때의 오판은 무시할 만함).

- **[하 · 해결됨] `js/input.js:38` — 입력이 막힌 동안 방향키가 페이지를 스크롤한다**
  - 문제: `isBlocked()`가 true이면 `preventDefault()` 전에 return한다. 그래서 승리·게임 오버 후 300ms 대기 동안과 오버레이가 열린 동안에는 방향키가 기본 동작(스크롤)을 한다.
  - 영향: 1280×800, 844×390처럼 세로 스크롤이 생기는 화면에서 보드가 살짝 밀릴 수 있다. 입력 자체는 올바르게 무시된다(디스패치로 확인).
  - 제안: 게임 키이면 막혀 있어도 `preventDefault()`하고 `onMove`만 건너뛴다. dialog가 열려 있으면 바깥이 inert라 버튼 조작에는 영향이 없다.

## Build 담당 요청 항목에 대한 답

- **`flushRemovals` / DOM 타일 수**: 정상. 위 28번 참고.
- **300ms 지연 중 입력**: 이동은 막힌다(`state.won && !keepPlaying`, `state.over`). 1차 때는 방향키 스크롤이 막히지 않았으나(수정 필요 3번), 2차에서 해결을 확인했다.
- **Esc 강제 닫힘(`close` 이벤트)**
  - 승리: `overlay.close()`로 강제로 닫자 `close` 처리기가 `keepPlaying`을 실행했다. `keepPlaying:true` 저장, live 영역 "게임을 계속합니다.", board 포커스까지 정상.
  - 게임 오버: 강제로 닫으면 `overlayType=null`, board 포커스. 이동은 계속 막히고 new_game은 확인 없이 바로 시작된다. 상태 불일치는 없다.
- **375px 4~5자리, 라이트 대비**: 통과(19, 22번).
- **세로가 짧은 가로 모드**: 보드가 화면 안에 들어간다. 다만 아래 참고 2번의 작은 문제가 있다.
- **`?preview=1`**: 통과(27번).
- **한글 자판·Ctrl/Cmd**: 통과(12, 13번).
- **spec과 다른 구현 5가지**: 문제를 일으키지 않는다.
  - `setBest` 추가, `reducedMotion` 함수 허용: 문제없음. 함수로 받아 OS 설정 변경을 바로 반영하는 편이 더 낫다.
  - 보드 `min(100%, 480px)`: `.app`의 좌우 padding 16px과 합쳐져 spec의 `min(100vw - 32px, 480px)`과 같은 결과다(375px에서 343px).
  - 미리보기 점수판 없음: spec도 "작은 점수판"을 선택적으로 적었고 카드에서는 보드만 있는 편이 깔끔하다.
  - `<dialog>`: `showModal()`의 inert로 포커스 트랩이 동작한다. 1차 때 남은 문제였던 숨김 버튼 CSS(수정 필요 1번)는 2차에서 해결됐다.

| --- | --- | --- |
| 1. `.btn[hidden] { display: none; }` | 통과 | 승리 창이 먼저 뜨는 판을 불러와 "계속하기"를 누르고, ←로 게임 오버를 만든 같은 세션에서 확인했다. 승리 창의 "새 게임" 버튼은 `display:flex`로 정상 표시됐다. 게임 오버 창의 `#overlay-secondary`는 `hidden=true`, `display:none`, 0×0이었다(이전 글자 "새 게임"이 남아 있어도 보이지 않음). 스크린샷에도 "다시 하기"만 보였고, 실제 Tab 키 뒤에도 포커스는 `overlay-primary`에 머물렀다 |
| 2. `bestAtStart` 저장·복원 | 통과 | 아래 4가지 경우를 확인했다 |
| 3. 막힌 동안에도 게임 키 `preventDefault` | 통과 | 아래 4가지 경우를 확인했다 |

수정 2번(`bestAtStart`) 확인 내용
- best 600, 판 점수 600, `bestAtStart:100`인 판을 불러와 게임 오버 → "최종 점수 600 · 최고 점수를 갱신했습니다!"가 나왔다.
- `bestAtStart`가 없는 예전 저장값도 오류 없이 로드됐다(타일 15개, 점수 600). 로드할 때 `bestAtStart:600`으로 다시 저장되고, 게임 오버 문구는 "최고 점수 600"이다. 정보가 없으니 예상되는 대체 동작이다.
- 잘못된 값 `bestAtStart:'<b>abc</b>'`는 무시되고 best로 대체됐다("최종 점수 300 · 최고 점수 600"). innerHTML로 들어가는 경로도 없다.
- 새 게임은 `bestAtStart`를 현재 best(492)로 저장했다.

수정 3번(`preventDefault`) 확인 내용
- 게임 오버·승리 직후 300ms 대기 중에 디스패치한 `ArrowUp`, `w`가 `defaultPrevented=true`였고 이동하지 않았다.
- 오버레이가 열린 동안 실제 ↓ 키를 3번 눌러도 `scrollY` 0이 유지되고 창도 열려 있었다(844×390, scrollHeight 406).
- 오버레이 버튼은 그대로 동작했다. 실제 Enter로 "다시 하기"가 새 게임을 시작했고, 실제 Space로 "계속하기"가 `keepPlaying:true`를 저장한 뒤 board로 포커스를 옮겼다. 디스패치한 Enter·Space·Tab은 `preventDefault` 되지 않았다.
- Ctrl/Meta/Alt+방향키는 여전히 가로채지 않는다.

회귀 확인
- 60회 연속 입력 뒤 DOM 타일 11개 = 보드 11개였다.
- 한글 자판 키, 점수·최고 점수 저장, 새 게임 두 번 누르기가 정상이었다.
- `?preview=1`은 키 입력을 바인딩하지 않아 `preventDefault`도 하지 않는다. 그래서 블로그 iframe이 방향키를 삼키지 않는다. 저장 키도 바뀌지 않는다.
- 콘솔 로그 0건.
- 저장 형식에 `bestAtStart` 필드가 추가됐지만 `deserialize`는 모르는 필드를 무시하므로 문제없다.

## 참고 (사소한 개선 제안)

0. (2차) `bestAtStart`가 없는 예전 저장값은 판을 시작할 때의 최고 점수를 알 수 없어 1차와 같은 판정을 한다. 업데이트 직후의 한 판에만 해당하므로 그대로 둬도 된다.

1. 게임 오버 오버레이가 강제로 닫히면(Esc 연타) 보드만 남는다. 이때 "게임이 끝났습니다. new_game으로 다시 시작하세요" 같은 announce를 하면 스크린리더 사용자가 덜 헷갈린다.
2. 가로 모드(`style.css:598-625`)에서 보드 높이 `100svh - 32px`에 `.app` 위 padding 16px과 아래 padding 32px이 더해져 세로로 16px 스크롤이 생긴다(844×390에서 scrollHeight 406). 아래 padding을 16px로 줄이거나 `100svh - 48px`로 맞추면 없어진다. 568×320에서는 푸터가 화면 아래로 밀리는데, 안내 문구라 허용할 만하다.
3. 한 이동에서 2048을 만들면서 동시에 게임 오버가 되면 승리 오버레이 없이 게임 오버만 뜬다(`main.js:226`). 매우 드문 경우이고 spec에 규정이 없어 현행 유지도 괜찮다. 원한다면 게임 오버 문구에 "2048 달성"을 덧붙일 수 있다.
4. `<dialog>`에 `showModal()`을 쓰므로 `aria-modal="true"`는 중복이다(해는 없음).
5. `initPreview`의 `serialize(createGame({ rng: () => 0 }))`는 `version` 값을 얻기 위한 우회다. `{ version: 1, cells, ... }`를 직접 쓰는 편이 읽기 쉽다(동작에는 영향 없음).
